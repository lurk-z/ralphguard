## บริบท: ทำไมต้องมีเอกสารนี้

โปรเจกต์มี 3 branch ที่เกี่ยวข้อง:
- **`frontend`** — ทำ UI/UX ไว้สวยงาม แต่ logic เบื้องหลังยังเป็น mock/placeholder
- **`GOD`** — ต่อ backend, catalog สารเคมี, QSAR model, AI จริงไว้ครบ แต่ UI เป็นเวอร์ชันเก่ากว่า
- **`integrate-ui`** (branch นี้) — เอาโครงหน้าตาของ `frontend` เป็นหลัก แล้วเสียบ logic ของ `GOD` เข้าไปทีละจุด

งานหลักคือ **"เอา logic ของ GOD มาต่อกับ UI ของฉัน"** ทำทีละฟีเจอร์ ตรวจสอบให้แน่ใจว่าใช้งานได้จริงก่อนไปฟีเจอร์ถัดไป

### ข้อจำกัดสำคัญของการทดสอบในเซสชันนี้

เครื่องที่ใช้พัฒนา **ไม่มี backend รันอยู่จริง** (ต้องมี Docker + Postgres + Redis) งานที่ต้องคุยกับ backend (AI แชท, ประเมินผลจริง, OCR, TTS) จึงถูกทดสอบด้วยการ **จำลองคำตอบ backend เอง (stub)** ในเบราว์เซอร์ ไม่ใช่ backend จริง — ควรทดสอบซ้ำอีกครั้งตอนมี backend ครบ

นอกจากนี้เครื่องมือทดสอบอัตโนมัติ **ขับเคลื่อน WebGL/3D render loop ไม่ได้เสถียร** (canvas ค้างที่ขนาด 300×150 default) ทำให้บางงานเกี่ยวกับโมเดล 3D ต้องตรวจสอบผ่านการอ่าน React props/state แทนการดูภาพจริง หรือรอให้ผู้ใช้ยืนยันด้วยภาพหน้าจอของตัวเอง

## ❌ สิ่งที่ยังไม่ได้ทำ / รู้ว่ายังขาด

1. **การยืนยันกับ backend จริงทั้งหมด** — ทุกฟีเจอร์ที่ต้องคุยกับ backend (แชท AI, เสียง, OCR, ประเมินผล, optimizeFormula) ทดสอบด้วยการจำลองคำตอบเองในเซสชันนี้ ยังไม่เคยเห็นทำงานกับ backend ที่รันจริง (Docker + Postgres + Redis + GROQ_API_KEY) ควรลองอีกรอบให้ครบ

2. **ความปลอดภัยของ `docker-compose.yml`** — พอร์ต `5432` (postgres) และ `8000` (backend) เปิดกับทุก network interface ไม่ใช่แค่ localhost ถ้ารันบน Wi-Fi ที่ไม่ไว้ใจ คนในวงเดียวกันอาจต่อ database ได้โดยไม่ต้อง login แนะนำเปลี่ยนเป็น `"127.0.0.1:5432:5432"` — **ยังไม่ได้แก้**

3. **Export/Import โปรเจกต์ข้ามเครื่อง** — ตอนนี้โปรเจกต์ผูกกับเบราว์เซอร์เครื่องเดียว เปลี่ยนเครื่อง/เบราว์เซอร์/ล้าง site data แล้วหายหมด ยังไม่มีปุ่ม export/backup

4. **โมเดล 3D ไม่ auto-repaint ตอนเปลี่ยนวัน** — ต้องคลิก/ลากบนโมเดลเองถึงจะเห็นสีใหม่ตามวันที่เลือก (ตรวจแล้วว่า GOD เองก็ทำงานแบบนี้ ไม่ใช่ของเราขาด แต่ถ้าอยากได้แบบ auto ต้องพัฒนาเพิ่มเติม)

5. **`api.listProjects`/`createProject`/`listProjectAssessments` ใน `api.ts`** — ฟังก์ชันเก่าที่เคยเรียก backend สำหรับจัดการโปรเจกต์ ตอนนี้ไม่มีใครเรียกแล้ว (ย้ายไป localStorage หมด) ยังไม่ได้ลบทิ้งเพราะ backend endpoint ยังมีอยู่จริง ไม่ใช่โค้ดตาย แต่ควรพิจารณาว่าจะเก็บไว้ทำไมต่อไป

6. **Settings page, /models page (global)** — ยังไม่ได้ตรวจสอบละเอียดว่ามี mock หรือ gap อะไรหลงเหลืออยู่ (ตรวจผ่านๆ แล้วดูปกติ แต่ไม่ได้ลงลึกเท่าหน้า assess/report)

## วิธีทดสอบทั้งระบบแบบเร็ว (ไม่มี backend)

ฟีเจอร์ต่อไปนี้ทดสอบได้ทันทีโดยไม่ต้องเปิด backend เลย:
- คลังสาร, น้ำเติมอัตโนมัติ, เทมเพลต, โหนดโมเดล, ทูลทิป, โปรเจกต์ในเครื่อง, ตำแหน่งกึ่งกลางโมเดล 3D, ตัวเลือกบริเวณตา

ฟีเจอร์ต่อไปนี้ **ต้องเปิด backend** (`docker compose up` หรือเทียบเท่า) ถึงจะเห็นผลจริง:
- แชท AI, เสียง, OCR, ประเมินผลจริง (Run), AI ปรับอัตราส่วน, รายงาน PDF ที่มีข้อมูลจริง (ไม่ใช่ sample)
