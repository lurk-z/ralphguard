# คำสั่งหลักสำหรับ Codex · ใช้ฐานเดิม

ให้ใช้ **ไฟล์นี้ไฟล์เดียวเป็นคำสั่งเริ่มงาน** สำหรับ FE หนึ่งคน เป้าหมายคือเดโมจากคำสั่งในแชตจริงบนหน้าจอ ไปถึงการส่งงานในห้อง การตรวจตัวอย่าง และการเกิดรุ่นที่ถูกต้องใน Nodes ผลทดลองและข้อความจาก Agent ใช้แหล่งข้อมูลจำลองที่เล่นซ้ำได้ก่อน เมื่อเดโมผ่านแล้วค่อยจับคู่เหตุการณ์กับ API ที่เพื่อนรับผิดชอบ

พาธในส่วน “อ่านจาก Vault” เริ่มจากโฟลเดอร์ที่มี START-HERE.md พาธขึ้นต้นด้วย frontend/ และ docs/ เริ่มจากราก repo ตรวจ checkout จริงก่อนตัดสินว่าอะไรยังขาด งานที่ค้างใน working tree อาจต่างจาก HEAD

## เรียกใช้เดโม Lab ที่ซ้อมแล้วบน jay-frontend

1. เก็บ Before ตาม [[JAY-FRONTEND-BASELINE]] เมื่อใช้โค้ดที่เตรียมไว้ได้ เปิด [Lab-Chat-Rehearsal.zip](Lab-Chat-Rehearsal.zip) ใน `Use-Prepared/` รายการใน ZIP เริ่มจาก `frontend/` ทุกไฟล์ เมื่อตรวจบนฐาน `9218cb5` ทั้ง 50 รายการเป็นไฟล์เพิ่ม ถ้าเริ่มจาก SHA อื่นให้เทียบรายชื่อก่อนคัดลอกลงรากของ checkout ที่ใช้พัฒนา
2. ชุดนี้มีหน้า `frontend/src/app/(dashboard)/lab-room/page.tsx` โค้ดห้อง แชต สถานี ระบบส่งงาน และชุดทดสอบ รวมถึงภาพโปรไฟล์ 5 รูปกับโลโก้ใน `frontend/public/` ให้นำภาพมาใช้ตามสิทธิ์ของรอบนั้น สำหรับรอบที่อนุญาตโมเดล ให้วาง GLB ทั้งหกตาม [[WEB-MODELS]] ในพาธด้านล่าง แยกเก็บ GLB ชุดเดียวไว้ใน Vault
3. ใน `frontend/src/app/(dashboard)/layout.tsx` เพิ่ม `import './lab-chat.css'` หนึ่งครั้ง ใช้ layout และ SessionProvider ของโครงการเดิม เริ่ม dev server ของ frontend เข้าด้วยบัญชีทดสอบแล้วเปิด `/lab-room?agentDemo=1` โหมดนี้ใช้ transport จำลอง ส่วนกรณีใช้โค้ดได้แต่ยังใช้โมเดลไม่ได้ ให้ต่อ `useAgentDemo` และรายการเลือก Agent กับแผง Lab ชั่วคราวที่ใช้รูปทรงหรืออักษรย่อที่ทำในงาน
4. เมื่อส่งงานจากหน้า Lab เดี่ยวได้จึงเพิ่มแท็บใน `frontend/src/app/(dashboard)/assess/page.tsx` และส่ง project ID ให้ `<LabRoomExplorer embedded projectId={projectId} />` ถ้าเก็บแท็บล่าสุดใน project workspace ให้เพิ่มค่า `lab` ใน `WorkspaceMode` และตัวอ่านค่าเดิมของ `frontend/src/lib/project-workspace.ts` สองจุดนี้เป็นงานเชื่อมของวันแข่ง ทำแยกจากการแตก ZIP เพื่อรักษา Assessment และ Nodes เดิม
5. จาก `frontend/` รัน `node --experimental-strip-types --test tests/lab-demo-handoff.test.ts tests/lab-demo-command-flow.test.ts tests/lab-demo-conversations.test.ts` ด้วย Node ที่รองรับการรัน TypeScript แล้วลองผ่านหน้าจอตาม [[AGENT-DEMO-QA]] รอบซ้อมตรวจ TypeScript และทดสอบ 22 กรณีจากไฟล์ที่แตกทับสำเนาซอร์สฐานโดยใช้ dependencies ในเครื่อง ส่วนผลทดสอบเบราว์เซอร์มาจาก working tree ของ `jay-sandbox`

ถ้ามีเฉพาะ Vault จะกู้ Component ที่เก็บ snapshot, GLB และชุด Lab ด้านบนได้ ชุด Lab อาศัย React, Next, providers และ helper ที่มากับฐาน `jay-frontend` ส่วนแท็บในหน้าโครงการต้องเชื่อมตามข้อ 4 ดู [[VAULT-AUDIT]] สำหรับขอบเขตของคลัง Component รุ่นก่อน

เมื่อใช้เฉพาะ Vault ให้เช็กตาราง “ถ้ามีเฉพาะ Vault จะกู้ Component ตัวไหนได้บ้าง” ใน [[VAULT-AUDIT]] ก่อนหยิบชิ้นใหญ่ โดยเฉพาะ VoiceAssistant และ FormulaGraph ที่มีซอร์ส V1 แต่ยังพึ่ง helper จาก repo สำหรับแชตใหม่ให้เริ่มจากชิ้น UI ที่ต้องใช้ เช่น Avatar, Button และ Popover แล้วเพิ่มเฉพาะ helper ที่เส้นทางเดโมเรียกจริง

## 3. ทำให้ครบหนึ่งเส้นทางก่อนขยายหน้าจอ

**จุดตรวจแรกคือพิมพ์สั่งงานใน Lab ได้จริง** เปิด Lab จากโครงการ เลือก Agent จากโมเดลหรือรายชื่อ พิมพ์แล้วกดส่ง ตรวจว่าข้อความและคำตอบอยู่ในแชตของคนที่เลือก เมื่อสิทธิ์โมเดลพร้อมให้ใช้ห้องและ Agent ตาม manifest ถ้าใช้ได้เฉพาะโค้ดให้เริ่มด้วยรูปทรงแทนบทบาท หลังจากนั้นจึงทดสอบเส้นทางส่งงานและเก็บหลักฐาน After โดยใช้โจทย์กับขนาดจอเดียวกับ Before

หน้ารายการแชตใช้รูปและชื่อบทบาทในห้องส่วนตัว พร้อมข้อความล่าสุดและเวลา แสดงกลุ่มตามงาน ให้ Director ตั้งชื่อจากโจทย์เมื่อใช้ API ในเดโมใช้กติกาจำลองตั้งชื่อ เก็บรหัสงานแยกจากชื่อเสมอ เปิดกลุ่มดูสมาชิกและคุยต่อได้ เมื่อหลายงานอยู่ในโครงการเดียวกันให้เปิดได้ตรงงานเดิมและเห็นเฉพาะข้อความของงานนั้น ชื่อผู้ส่งใช้ตัวเล็กสีเทาชิดรูป ให้ข้อความอ่านเด่นกว่า ทดสอบการตามงานและการตอบก่อนปรับรายละเอียดหน้าตา

1. เริ่มจากสถานะกลางที่แยกผู้ใช้ โครงการ การทดลอง งาน รุ่น และขวด บันทึกผู้ส่ง ผู้รับ ข้อความต้นทาง ลำดับเหตุการณ์ และรหัสส่งมอบเดิมเมื่อ retry แยก storage จำลองจาก Assessment จริง
2. ให้แชตตีความคำสั่งไทยในขอบเขตเดโม ถามผลอย่างเดียวต้องไม่สร้างสูตรใหม่ งานตรงหน้าที่ทำเองได้ สองคนคุยในเธรดเดิม คนที่สามรับงานจึงต่อในกลุ่มเดียวของโครงการ โดยติดรหัสการทดลองทุกครั้ง
3. แสดงผู้ใช้ฝั่งขวากับรูปจาก session, Agent ฝั่งซ้ายมีรูปและชื่อเมื่อเปลี่ยนผู้พูด ใต้ข้อความงานของแต่ละ Agent ใช้ checklist พับได้ของงานนั้น เวลาและ copy แสดงเมื่อ hover/focus, ปุ่ม copy เปลี่ยนไอคอนในพื้นที่เดิม, ประวัติลบด้วยสองคลิก, เปิดใหม่ไม่เล่น typing ย้อน ขณะกดไมค์แสดง listening และเส้นเสียง
4. เมื่อส่งแล้วแสดงข้อความทันที ถ้าคำตอบพร้อมก่อนถึงให้เร่งการเดินภายในเพดานธรรมชาติ และแสดงคำตอบหลังส่งถึงและตอบรับ ถ้ารอผู้ใช้ให้เลข 1 สีแดงเหนือหัว เปิดคำถามส่วนตัวได้และล้างเมื่อส่งคำตอบสำเร็จ กลุ่มเห็นข้อสรุป งานอิสระไปต่อได้ เมื่อ retry อัตโนมัติหนึ่งครั้งยังล้มเหลวให้ปุ่มลองอีกครั้งในข้อความเดิม
5. เชื่อมการตรวจสี่ด้านกับขวดและ Nodes หลัง Analyst ปิดผลครบ (รวมด้านที่ระบุเหตุผลว่าสรุปไม่ได้) ก่อนผลแรกแสดงสถานะจริงและปุ่มเปิดตัวอย่าง กล่องสารชี้ขึ้นไปรุ่นของตัวเอง สร้างสองกิ่งพร้อมกันใช้ V2-A / V2-B; ถ้า V2 มีอยู่ก่อนให้เก็บชื่อเดิม สามารถลองเก็บขวดในตู้หรือทิ้งได้ Evaluator สรุปข้อดี ข้อจำกัด และเหตุผลที่แนะนำในกลุ่ม
6. รัน QA สองเรื่องให้จบ ผู้ใช้เปลี่ยนข้อห้ามหลัง V1 และผลนอกขอบเขตโมเดลที่ต้องขอหลักฐานเพิ่ม รายละเอียด assertion และสิ่งที่ต้องถ่ายประกอบอยู่ใน [[AGENT-DEMO-QA]] ตรวจ 390px, ปิด/เปิดแชต, เปลี่ยนแท็บระหว่างส่ง, เปลี่ยนโครงการ, โหลดใหม่ และคำตอบรับซ้ำ วัดเวลาโหลด/FPS ของฉากจริงแยกจากตัวเลข gzip ของชิ้น UI
7. หลัง MVP ใช้ได้ค่อยเก็บ responsive หน้ารอง ปรับ Login และ Landing ให้โหลดโมเดลล่าสุดเมื่อจำเป็น ตรวจ typecheck, build และชุดทดสอบที่เกี่ยวข้องตาม script ใน checkout สรุปเส้นทางที่รันจริง โหมดข้อมูล ข้อจำกัด และไฟล์ที่แก้ จึงจด component รุ่นที่ผ่าน QA ลง Vault
