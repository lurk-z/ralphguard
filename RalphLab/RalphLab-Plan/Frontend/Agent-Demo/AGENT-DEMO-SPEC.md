# Ralph Lab · เดโมการส่งงานผ่านแชต

ผู้ใช้คลิก Analyst แล้วพิมพ์ “ช่วยทำคลีนเซอร์สำหรับผิวเป็นสิวง่ายให้หน่อย” ได้ทันที Analyst รับผิดชอบการคัดกรอง จึงเชิญ Director มารับโจทย์ เมื่อ Director มอบหมายให้ Researcher เป็นคนที่สาม งานเดียวกันปรากฏในกลุ่มของโครงการ ผู้ใช้เห็นว่าใครกำลังทำอะไรและเปิดดูผลจากขวดหรือ Nodes ได้

เอกสารชุดนี้ใช้สำหรับสร้างและตรวจเดโม FE ด้วยข้อมูลสมมติ เมื่อพฤติกรรมผ่านจึงจับคู่เหตุการณ์กับ API ของทีม Backend เริ่มทำตาม [[AGENT-DEMO-BUILD]] ซ้อมด้วย [[AGENT-DEMO-QA]] หรือคัดลอก [[AGENT-DEMO-CLAUDE-PROMPT]] ไปสร้างจากศูนย์

## ใครรับงานอะไร

| ผู้รับ | ทำเองได้ | เมื่อพบปัญหา |
|---|---|---|
| Lab Director | รับโจทย์ กำหนดวัตถุประสงค์ ข้อจำกัด เกณฑ์และจำนวนรอบ | แจกงานหลายบทบาท ถามผู้ใช้เมื่อคำตอบเปลี่ยนทิศทางการทดลอง |
| Researcher | ค้นบันทึกหลักฐานตัวอย่าง ระบุหน้าที่สารและข้อมูลที่ยังขาด | ส่งทางเลือกพร้อมเหตุผลให้ Formulation Scientist หรือแจ้งว่าหลักฐานยังไม่พอ |
| Formulation Scientist | เลือกส่วนผสม สัดส่วน บันทึกเหตุผล และสร้างขวดประจำรุ่น | ส่งขวดให้ Analyst ส่งคำถามเรื่องหลักฐานกลับให้ Researcher |
| Analyst | ตรวจผลจำลองด้านผิว ตา แพ้สัมผัส และพิษเฉียบพลัน พร้อมความไม่แน่นอน | รับหน้าที่ตรวจขอบเขตโมเดลด้วย ขอข้อมูลเพิ่มจาก Researcher และระบุผลที่สรุปไม่ได้ |
| Evaluator | เทียบผลกับข้อบังคับและเป้าหมาย พิจารณาว่ามีหลักฐานพอจะแนะนำรุ่นใด | ผิวสูงกว่าเกณฑ์ส่งให้ Researcher กับ Formulator สูตรผิดข้อห้ามส่งให้ Formulator หลักฐานขาดส่งให้ Researcher ผลนอกขอบเขตส่งให้ Analyst |

## ผู้ใช้จะเห็นอะไร

- เปิดรายการแชตในแผง Lab เห็นรูป ชื่อ และข้อความล่าสุดก่อนไปต่อ ส่วนตัวใช้รูป Agent และชื่อบทบาทภาษาอังกฤษ กลุ่มแสดงชื่องานที่ตั้งจากโจทย์และเปิดดูสมาชิกที่รับงานแล้วได้ ชื่อผู้ส่งในบทสนทนาใช้ตัวเล็กสีเทาชิดรูป ผู้ใช้ดูข้อความได้ก่อนอ่านรายละเอียด checklist
- กลุ่มอ้างโครงการเดียวกัน แต่รายการแชตแยกตามรหัสงาน เปิดสองงานพร้อมกันแล้วชื่อ ประวัติ ผู้รับผิดชอบ และคำตอบของแต่ละงานต้องตามรหัสเดิม เดโมตั้งชื่อแบบกำหนดกติกาไว้ จุดต่อ API รองรับชื่อที่ Agent ตั้งให้ภายหลัง

- **แชตส่วนตัว** ถามหรือสั่งได้ทุกบทบาท คำถามอ่านผล เช่น “V1 มีอะไรบ้าง” ตอบจากข้อมูลเท่าที่มี คำสั่ง เช่น “เอาน้ำหอมออกจากรุ่นถัดไป” จึงเปิดงานใหม่ ถ้อยคำที่กำกวมให้ถามกลับก่อนสร้างสูตร
- **หนึ่งหรือสองคน** เจ้าของแชตทำงานเล็กเองได้ เมื่อเชิญคนที่สองให้คนที่สองเข้ามาตอบในเธรดเดิม แสดงรูปและชื่อที่จุดเปลี่ยนผู้พูด นับเฉพาะ Agent ที่รับผิดชอบงานนั้น
- **ตั้งแต่คนที่สาม** ใช้กลุ่มเดียวต่อโครงการ ทุกข้อความของการทดลองมีชื่อหรือรหัสการทดลอง เมื่อผู้ใช้ย้อนมาแชตส่วนตัว มีข้อความสรุปและลิงก์ไปตำแหน่งงานเดิมในกลุ่ม สั่งงานเล็กเรื่องใหม่เป็นการส่วนตัวได้ต่อ
- **ใครพูดกับใคร** ผู้ใช้อยู่ขวาพร้อมรูปจาก Google session และใช้อักษรย่อเมื่อรูปโหลดพลาด Agent อยู่ซ้ายพร้อมรูปประจำบทบาท เมื่อพูดติดกันใช้หัวผู้พูดครั้งเดียว บรรทัดส่งงานระบุ “Researcher → Formulation Scientist · ส่งตัวเลือกเบสล้าง · D01” พร้อมสถานะกำลังส่งหรือรับแล้ว แยกสีด้วยข้อความและไอคอนด้วย
- **ความคืบหน้าราย Agent (ข้อ 2B)** ใต้ข้อความที่ Agent รับทำงานมีรายการพับได้ของงานนั้น เช่น “Analyst · ตรวจ V2-B · 2/4” ภายในมี ✓ ผิวเสร็จแล้ว, ✓ ตาเสร็จแล้ว, ◉ ตรวจแพ้สัมผัส, ○ รอพิษเฉียบพลัน แถวอัปเดตในข้อความเดิม พอเสร็จแสดงผลสั้น ๆ ประวัติที่เปิดใหม่แสดงสถานะล่าสุดทันที ข้อความทั่วไปไม่ต้องมีรายการขั้นตอน
- **เหนือศีรษะ** ระหว่างรอให้ขึ้น `thinking...` เมื่อเริ่มงานใช้คำสั้น ๆ เช่น “กำลังตรวจ V1” เมื่อรอผู้ใช้ให้เลข **1 สีแดงแบบไม่มีกรอบ** มีชื่อที่โปรแกรมอ่านหน้าจออ่านได้ คลิกเพื่อเปิดคำถาม เลือกตัวเลือกหรือพิมพ์เอง เปิดอ่านแล้วเลขยังอยู่ ตอบสำเร็จจึงหาย กลุ่มได้รับเฉพาะข้อสรุป อีกกิ่งทำงานต่อได้ ระหว่างว่างให้หัวตัวละครโล่ง
- **คุยต่อได้ระหว่างส่งของ (ข้อ 1A)** ผู้ส่งแจ้งทันทีว่าได้ส่งอะไรให้ใคร คำตอบที่พร้อมเร็วรอแสดงหลังส่งถึงตัวผู้รับในฉาก เร่งการเดินและจังหวะก้าวได้ภายในเพดานที่ดูเป็นธรรมชาติ ผู้ใช้สลับหน้าได้ เมื่อกลับมาให้แสดงจุดที่งานดำเนินถึงแล้ว
- **การกู้คืน (ข้อ 3A)** เมื่อส่งไม่สำเร็จให้ลองอัตโนมัติอีกหนึ่งครั้งด้วยรหัสงานเดิม ถ้ายังไม่สำเร็จ แสดงปุ่ม “ลองอีกครั้ง” ที่ข้อความส่งงานเดิม งานซึ่งไม่ขึ้นกับการส่งครั้งนั้นเดินต่อได้
- **รูปแบบภาพ** ธีมขาว สีเรียบ อ่านตัวอักษรได้บนมือถือ ใช้ประวัติแชตและเครื่องมือพิมพ์เดิม พื้นที่ห้องย่อตามแผงแชต ผู้ใช้กดดูรายละเอียดสูตร ผล และที่มาจากขวดได้ หน้าสนทนาให้บทสนทนาเป็นเนื้อหาหลัก

## ความหมายของรุ่นใน Nodes

เปิดการทดลองที่กำลังดูใน Lab เป็นค่าเริ่มต้น และสลับการทดลองของโครงการได้จากหัวหน้า Nodes ก่อนผลแรกแสดง “กำลังตรวจ V1” ตามสถานะจริง พร้อมปุ่มเปิดผังตัวอย่างแยกที่ติดป้ายชัดเจน เมื่อ Analyst ปิดผลทั้งสี่ด้าน แต่ละด้านมีผลหรือมีเหตุผลที่สรุปไม่ได้ จึงเผยแพร่ Node ของรุ่นนั้น

ในภาพร่าง กล่องใหญ่ด้านบนคือหนึ่งรุ่น กล่องข้างล่างแต่ละใบคือสารหนึ่งตัวพร้อมสัดส่วน เรียงแถวละไม่เกินสี่ตัว เส้นโค้งสีเทาชี้จากสารขึ้นไปที่รุ่น สำหรับรุ่นลูกให้ใส่ “ต่อจาก V1” กับรายการที่เปลี่ยน จัดรุ่นเป็นชั้นบนลงล่าง ผู้ใช้ซูม เลื่อน และจัดตำแหน่งกล่องได้ การแก้สูตรเริ่มที่แชตหรือห้อง Lab

- ถ้าวางแผนลองสองทางพร้อมกัน ให้จองชื่อ V2-A และ V2-B ตั้งแต่แตกกิ่ง ถ้าเดิมมีลูกเดียวชื่อ V2 แล้วผู้ใช้ขอทางเลือกเพิ่ม ให้คง V2 และตั้งกิ่งใหม่ V2-B ทั้งคู่มีแม่เป็น V1
- เมื่อเปลี่ยนข้อกำหนด ให้เก็บรุ่นที่ส่งไปแล้วกับผลเดิม สร้างรุ่นลูก พร้อมเหตุผลและข้อความที่เป็นที่มาของการเปลี่ยน จำกัดเดโมที่ V1 และรุ่นลูกไม่เกินสองขวด
- Evaluator สรุปในกลุ่ม รุ่นที่แนะนำมีข้อดีหนึ่งบรรทัด ข้อจำกัดหนึ่งบรรทัด และลิงก์ไปข้อความสรุปเต็ม ข้อมูลไม่พอให้บอกว่า “ยังเลือกไม่ได้” คะแนนคัดกรองสี่ด้านรองรับการเปรียบเทียบความเสี่ยงเบื้องต้น ส่วนเป้าหมายด้านสิวต้องการหลักฐานประสิทธิผลต่างหาก
