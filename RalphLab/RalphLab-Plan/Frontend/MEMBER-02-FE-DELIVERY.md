# สมาชิกคนที่ 2 · Frontend, 3D, rig และ CCTV

**งานที่ต้องส่ง** เปิดโครงการหนึ่งงาน เลือกเหตุการณ์ส่งมอบหนึ่งรายการ แล้วกดจากเจ้าหน้าที่ → ขวด → สูตรในกราฟได้ ทั้งสามจุดอ้าง `event_id` เดิมและเปิดสูตรรุ่นเดียวกัน ผู้ทดสอบเห็นว่าใครส่งอะไรให้ใคร เพราะอะไร และมีผลหรือหลักฐานอะไรให้ดู เมื่อปิดภาพ 3D ยังทำสิ่งเดียวกันจากรายการงานได้ อ่านโจทย์และกฎของทั้งทีมใน [[TEAM-MVP-GUIDE]]

## ขอบเขตของเรา

| เราทำใน FE | ข้อมูลหรือบริการที่ขอจากทีม Backend/Agent |
|---|---|
| โหลดโมเดล จัดกล้อง ผูกตัวละครกับบทบาท เล่นท่า และทำพื้นที่ให้คลิก | รหัสเจ้าหน้าที่ ผู้ส่ง ผู้รับ และสถานะของใบงาน |
| แชตส่วนตัวและกลุ่ม แสดงผู้ส่ง การรับงาน ขั้นตอนที่ Agent รายงาน และข้อความสรุป | ข้อความ เหตุการณ์การทำงาน หลักฐานที่ใช้ และชื่อกลุ่มจากระบบงาน |
| แสดงรุ่นสูตร ถาดทั้งสี่ กราฟ ตาราง และผลเปรียบเทียบ | ข้อมูลเวอร์ชันกับรุ่นแม่ ผลรายสาร วิธีรวมผล รุ่นโมเดล ความเชื่อมั่น ขอบเขต และที่มา |
| เปิดคำถาม/คำอนุมัติ ส่งการตัดสินใจ แล้วแสดงผลตอบกลับ | กฎเลือกผู้รับงาน การตรวจสิทธิ์ งบ ข้อจำกัดสาร และผลยืนยันการตัดสินใจ |
| อ่านสถานะเมื่อเปิดหน้าใหม่ แสดงเหตุขัดข้อง และให้ลองซ้ำผ่านสัญญาเดิม | สถานะที่บันทึกไว้ ลำดับเหตุการณ์หรือวิธีกลับมารับงานต่อ และการรับคำสั่งซ้ำอย่างปลอดภัย |

FastAPI, ฐานข้อมูลและ migration, การเก็บคีย์/เรียกผู้ให้บริการ AI, การฝึกหรือปรับ QSAR, การคำนวณคะแนน และการเขียน eLabFTW อยู่ฝั่งบริการ หน้าจอแสดงผลลัพธ์หรือสถานะรอที่บริการคืนมา

## จุดเริ่มจากโค้ดจริง

พาธทั้งหมดนับจาก root ของ `ralphguard` ตรวจจาก working tree ของ `jay-sandbox` ส่วนฐาน Before ที่ตรวจในเครื่องคือ `jay-frontend` ที่ `9218cb5` เก็บหลักฐาน Before ตาม [[JAY-FRONTEND-BASELINE]] ก่อนนำงานเข้าวันแข่ง

ชื่อใน asset เดิมมี `director`, `researcher`, `formulator`, `analyst`, `evaluator` ส่วนชื่อบทบาทที่แสดงในแผนใหม่อยู่ในคู่มือทีม ขอรายการจับคู่ `agent_id → ชื่อบทบาท → avatar/rig` จากสมาชิกคนที่ 1 ก่อนใส่หน้าที่หรือหลักฐานให้ตัวละคร โดยเฉพาะ Chemical Data Curator กับ QSAR Model Scientist

## เริ่มก่อนด้วยเหตุการณ์หนึ่งรายการ

ขอตัวอย่างจากสมาชิกคนที่ 1 อย่างน้อยหนึ่งเส้นทาง **V1 → ส่งใบงานจริง → V2-A** พร้อมตัวอย่าง “ข้อมูลไม่พอ”, “รออนุมัติ” และ snapshot ตอนเปิดโครงการซ้ำ ใช้รูปแบบข้อมูลที่ทีมตกลงแล้ว ชื่อฟิลด์เสริมในตัวอย่างข้างล่างเป็นเพียงตัวช่วยคุยกับทีม

| เหตุการณ์ตัวอย่างสำหรับทดสอบ FE | ค่าเดียวกันที่ควรตามไปเจอ |
|---|---|
| `event_id = demo-014` · โครงการ `P1` · รุ่น `V1` · มีเวลาเกิดเหตุการณ์ | คลิกบรรทัดส่งมอบในแชตหรือรายการงาน แผงรายละเอียดแสดงเหตุการณ์นี้ |
| ใบงาน `W3` จาก Computational Toxicologist ถึง Formulation Chemist เกี่ยวกับตัวอย่าง `S1` | คลิกผู้รับใน CCTV เห็นใบงาน W3 คลิกขวด S1 เห็นสูตร V1 และไปยังโหนด V1 ได้ |
| ผลอ้างอิง `R1` กับหลักฐาน `E1` ของ V1 | คลิกถาดด้านผิวเห็น R1 และหลักฐาน E1 เมื่อมีเหตุการณ์ใหม่สร้าง V2-A ให้โหนดลูกอ้างเหตุการณ์สร้างของตัวเองและชี้รุ่นแม่ V1 |

**ใช้รหัสให้ถูกหน้าที่** `event_id` ระบุว่าเกิดอะไรขึ้นหนึ่งครั้ง ส่วน `version_id` ระบุสูตรซึ่งมีได้หลายเหตุการณ์ เมื่อผู้ใช้เปิดจากเหตุการณ์ ให้เก็บโครงการ เหตุการณ์ และรุ่นที่เลือกไว้ด้วยกันใน FE เมื่อเปิดจากขวดที่มีหลายใบงาน ให้แสดงเหตุการณ์ที่เลือกหรือให้เลือกจากประวัติ ก่อนเปิดกราฟ ตรวจว่าขวด สูตร และ run อยู่ในโครงการและรุ่นเดียวกัน ถ้าผู้ใช้ถาม V2 ขณะเลือก V1 ให้เปิดผลที่จับคู่กับ V2 ได้จริง หรือแจ้งให้เลือกรุ่นที่ต้องการ

**ตกลงก่อนต่อข้อมูลจริง** ให้ทีมยืนยันรหัสและลำดับเหตุการณ์ วิธีอ่าน snapshot วิธีระบุเหตุการณ์ก่อนมี V1 และข้อมูลสำหรับคำขออนุมัติ หากงานยังไม่มีรุ่น ให้แสดงว่ารอสร้างสูตร การแสดง “ส่งแล้ว” ใช้เหตุการณ์มอบหมาย ส่วนเครื่องหมาย ✓ ใช้เมื่อได้รับการยืนยันถึงผู้รับ การเดินถึงโต๊ะทำให้แอนิเมชันจบเท่านั้น

## ลำดับทำ FE และวิธีดูว่าแต่ละช่วงเสร็จ

| ลำดับ | ลงมือทำ | ผ่านเมื่อ |
|---|---|---|
| 1 · จุดเริ่มเดโม | เก็บ Before ของ Lab/Nodes จากฐานวันแข่ง เปิดโปรเจกต์กับแชตที่เลือก Agent ได้ ใช้ fixture ที่ติดป้าย “ข้อมูลจำลอง” ตามสัญญาข้อมูล | พิมพ์โจทย์จาก Agent หนึ่งตัว เห็นคำตอบ และเปิดใบงานที่ส่งถึงผู้รับได้จากแชตนั้น |
| 2 · ทำ workflow ในมุมรายการ | แยกข้อมูลตามผู้ใช้และโครงการ รองรับข้อความส่วนตัว/กลุ่ม ผู้ส่ง ผู้รับ งานที่รอคำตอบ และรายงานขั้นตอนที่ระบบส่งมา ผูกทุกบรรทัดที่เป็นเหตุการณ์กับหน้ารายละเอียด | ส่งใบงานเดิมซ้ำแล้วเกิดหนึ่งรายการ ผู้รับมีงานในแชตของตัวเอง กดจากสถานะรอแล้วเปิดคำขอที่ตรงรุ่น |
| 3 · ผูกห้องกับใบงาน | เปิดมุมกล้องรับโจทย์ โต๊ะพัฒนาสูตร และสถานีคัดกรอง ใช้ idle/walk/รับส่งของเดิม แสดงสถานะลอยเหนือเจ้าหน้าที่ ให้ขวดกดได้ | กดเจ้าหน้าที่และขวดหลังการส่งงานหนึ่งครั้งแล้วได้ W3/V1 ตามตัวอย่าง ผู้ใช้ตามงานในรายการต่อได้ระหว่างโหลด GLB หรือเมื่อปิด 3D |
| 4 · แสดงผลและ lineage | ใช้ผลสี่ endpoint ที่บริการให้มา พร้อมแหล่งที่มา วิธีรวมผล และข้อจำกัด ทำกราฟบนลงล่างจากเลขรุ่นแม่และเปรียบเทียบ V1 กับ V2-A | ระบุได้ว่ารุ่นลูกเปลี่ยนอะไร เพราะหลักฐานใด ด้านใดดีขึ้นหรือแย่ลง และด้านใดยังสรุปไม่ได้ คะแนนศูนย์แยกจากข้อมูลขาด ถ้าไม่มี V2 จะไม่วาดผล V1 ใต้คำขอ V2 |
| 5 · เปลี่ยนเป็นข้อมูลจริง | ใช้ adapter เดิมรับเหตุการณ์จาก Backend โหลด snapshot เมื่อกลับเข้าโครงการ ลองส่งซ้ำหรือเชื่อมต่อใหม่ และรับผลอนุมัติจากบริการ | ทำเส้นทางเดิมซ้ำด้วยการส่งใบงานจริงอย่างน้อยหนึ่งครั้ง ตัวละคร ขวด และโหนดตรงกับรหัสจากบริการ รีเฟรชแล้วยังคงใบงาน รุ่น และสถานะเดิม |
| 6 · ส่งให้คนทดสอบและคนเดโม | ส่งโครงการ รุ่นต้นทาง/รุ่นลูก รหัสเหตุการณ์ที่กดตามได้ บัญชีหรือโหมดที่ใช้ และจุดสังเกต ถ่าย Before/After ด้วยโครงการและมุมกล้องเทียบกันได้ | สมาชิกคนที่ 3 ทวนผลได้เอง สมาชิกคนที่ 4 เปิดเหตุการณ์นั้นจากห้องและกราฟ พร้อมสาธิตแบบปิด 3D ได้ |

ถ้าต้องตัดงาน ให้รักษาเส้นทาง **ส่งใบงาน → เปิดขวด → เทียบ V1/V2-A** กับคำเตือนผลคัดกรองก่อน งานเพิ่มฉาก ตกแต่งห้อง ทำรอยผิวละเอียด และเพิ่มแอนิเมชันนอกเส้นทางอยู่หลังการซ้อมรอบแรก

**กรอบ 8 ชั่วโมงสำหรับ FE คนเดียว** เป็นประมาณการสำหรับกรณีที่ใช้ห้องและ rig เดิมได้ เริ่มนับจากเวลาที่ลงมือพัฒนา

| เวลา | เป้าหมายที่ต้องลองกดได้ |
|---|---|
| 0:00–0:45 | เก็บ Before ตกลงตัวอย่างข้อมูลกับสมาชิกคนที่ 1 และรหัสที่ใช้เลือกงาน |
| 0:45–2:15 | แชตรับโจทย์ รายการส่งมอบ และรายละเอียดของเหตุการณ์หนึ่งรายการด้วย fixture |
| 2:15–3:45 | เลือกผู้รับกับขวดจาก CCTV แล้วเปิดข้อมูลใบงานและรุ่นสูตรเดิม |
| 3:45–5:15 | เปิดโหนดจากขวด เทียบ V1/V2-A และอ่านผลสี่ด้านรวมถึง unknown |
| 5:15–6:30 | ตรวจจุดเชื่อมด้วยใบงานจริงจาก Backend และเทียบรหัสที่ได้ทั้งสามหน้ากับข้อมูลต้นทาง |
| 6:30–8:00 | ทดสอบเคสซ้ำ รีเฟรช ปิด 3D และส่งโครงการที่ซ้อมแล้วให้ผู้ทดสอบกับผู้นำเสนอ |

ถ้ากติกาให้ใช้เฉพาะ prompt ให้เริ่มจากแชต รายการใบงาน และกราฟอ่านอย่างเดียวก่อน ใช้ตัวแทนเจ้าหน้าที่และขวดที่คลิกได้ระหว่างเตรียมโมเดล หากบริการยังไม่ส่งเหตุการณ์ ให้ซ้อมต่อด้วย fixture และคงสถานะรอบรวมทีมเป็น “รอตรวจด้วย Backend จริง”

## จุดเสี่ยงที่ต้องทดสอบบนหน้าจอ

- **กราฟผิดสูตร** โค้ดแชตใน sandbox ตัดสินว่าจะแนบกราฟจากคำในคำถาม แล้วหยิบผลของสูตรที่เลือกอยู่ ดู `frontend/src/components/three/skincare-lab/chat/useLabAgentChat.ts` ทดสอบถาม V2 ขณะเลือก V1 และตรวจทั้งข้อความ ชื่อรุ่น และรหัสผลก่อนส่งมอบ
- **สลับผู้ใช้หรือรีเฟรช** ประวัติ API แบบเดิมตั้ง storage key ตามโครงการ ขณะที่เดโมเก็บเฉพาะข้อความส่วนตัวบางส่วนข้ามการรีโหลด ทดสอบบัญชี A/B บนเบราว์เซอร์เดียวกัน และทดสอบคืนกลุ่ม ใบงาน และกราฟจากสถานะของโครงการ
- **โหมดแชตกับการส่งงานจริง** จุด `POST /api/chat/` ที่ตรวจใน sandbox ใช้ Groq ตอบรายตัว การเชื่อม OpenAI ตามแบบทีมและการส่งใบงานข้าม Agent ให้ทดสอบกับบริการของสมาชิกคนที่ 1 แยกกัน การได้รับข้อความจากโมเดลเพียงหนึ่งข้อความยังยืนยันการรับใบงานไม่ได้
- **สองแหล่งให้ผลไม่ตรงกัน** ใช้ run และ version ที่ยืนยันแล้วร่วมกันทั้งถาด แชต และกราฟ ถ้าหลักฐานเป็นผลลบด้านแพ้สัมผัส ให้ช่องระคายเคืองผิวแสดง unknown เมื่อยังไม่มีหลักฐานด้านผิว แสดงข้อความกำกับแบบตรงตาม [[TEAM-MVP-GUIDE#โจทย์และสิ่งที่ผู้ใช้ได้รับ]]
- **รออนุมัติหรือเชื่อมต่อขาด** แสดงคำขอและรุ่นที่กำลังรอ ปิดการกดซ้ำระหว่างรอผล หากล้มเหลวให้ลองจากใบงานเดิม เมื่อแต่ละหน้ากลับมาออนไลน์ให้เปิดสถานะล่าสุดตามรหัสเดิม
- **ความพร้อมของชุดแข่ง** งานที่ตรวจอยู่บน `jay-sandbox` และมีซอร์สแชตที่ยังไม่อยู่ใน Git ชุด `Use-Prepared/Lab-Chat-Rehearsal.zip` ที่ตรวจยังขาด `AssessmentReply.tsx` และ `chat-assessment.ts` ซ้อมบนสำเนาของ `jay-frontend` และบันทึก commit หรือรุ่นของชุดที่ใช้ตามเงื่อนไขการแข่งขัน

## เกณฑ์ส่งมอบของสมาชิกคนที่ 2

- [ ] **รอบ FE** ใช้ fixture ระบุแหล่งข้อมูลครบ กดเจ้าหน้าที่ ขวด และโหนดจากเหตุการณ์เดียวกัน ผลของแต่ละจุดตรงกัน
- [ ] **รอบรวมทีม** ส่งหนึ่งใบงานผ่าน Backend จริง ยืนยันจากรหัสและสถานะของผู้รับ เปิดผลและหลักฐานที่ผูกกับรุ่นเดียวกัน พร้อมทวนกรณีข้อมูลไม่พอหรือรออนุมัติ
- [ ] **รอบทดสอบ** ผ่านห้าเคสหลักและเคสรีเฟรชใน [[TEAM-MVP-GUIDE#เกณฑ์รับงานของทีม]] รวมทั้งปิด 3D แล้วเดินงานต่อได้
- [ ] **รอบส่งงานแข่ง** คนอื่นในทีมเปิดโครงการเดียวกันแล้วเล่า V1 → V2-A ได้จากหลักฐาน มีภาพ Before/After และรหัส commit ของงานที่ใช้สาธิต
