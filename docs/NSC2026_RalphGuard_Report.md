## บทคัดย่อ

การทดสอบความปลอดภัยของสารเคมีและเครื่องสำอางในปัจจุบันยังต้องอาศัยการทดลองในสัตว์ ซึ่งใช้เวลานาน มีต้นทุนสูง และขัดต่อหลักจริยธรรม โครงการ **RalphGuard** จึงพัฒนาแพลตฟอร์มเว็บสำหรับ**คัดกรองความเสี่ยงเบื้องต้น**ของสารเคมีและสูตรผลิตภัณฑ์ด้วยแบบจำลองเชิงคำนวณ (in-silico) โดยไม่ต้องทดลองกับสัตว์หรือผิวจริง ระบบใช้แบบจำลอง **QSAR (Quantitative Structure–Activity Relationship)** ทำนายความเสี่ยง 4 ด้าน ได้แก่ การระคายเคืองผิวหนัง การระคายเคืองดวงตา การแพ้ผิวหนัง และความเป็นพิษเฉียบพลัน จากโครงสร้างโมเลกุล (SMILES) โดยคำนวณ molecular descriptors และ molecular fingerprints แล้วป้อนเข้าสู่แบบจำลอง Soft-Voting Ensemble

จุดเด่นของระบบคือการยึดหลักการตรวจสอบความถูกต้องของ QSAR ตามแนวทาง OECD ทั้ง 5 ข้อ โดยเฉพาะการมี **Applicability Domain (AD)** และ **ระบบความเชื่อมั่น 3 ชั้น** ที่ทำให้ระบบ "รู้ตัว" ว่าสารใดอยู่นอกขอบเขตที่แบบจำลองเชื่อถือได้ นอกจากนี้ยังผนวกเทคโนโลยีปัญญาประดิษฐ์เพิ่มเติม ได้แก่ **ผู้ช่วย AI เชิงสนทนา (Chatbot/NLP)** ที่ทำงานตามคำสั่งภาษาไทยธรรมชาติได้ **เทคโนโลยีเสียง (Speech: TTS/STT)** และ **การประมวลผลภาพ (OCR)** ที่อ่านรายการส่วนผสมจากรูปฉลากผลิตภัณฑ์แล้วแปลงเป็นสูตรเพื่อประเมินได้อัตโนมัติ ผลลัพธ์ทั้งหมดถูกแสดงผลบน**แบบจำลองใบหน้า 3 มิติ**เพื่อให้เข้าใจง่าย ผลการทดสอบพบว่าแบบจำลองทั้ง 4 ด้านมีค่า AUC ระหว่าง 0.886–0.926 ซึ่งเพียงพอต่อการใช้เป็นเครื่องมือคัดกรองเบื้องต้นก่อนการทดสอบจริง

## Abstract

Conventional safety testing of chemicals and cosmetics still relies heavily on animal testing, which is time-consuming, costly, and ethically problematic. **RalphGuard** is a web platform for **in-silico preliminary risk screening** of chemical substances and product formulations, without the use of animals or real skin. The system employs **QSAR (Quantitative Structure–Activity Relationship)** models to predict four toxicological endpoints — skin irritation, eye irritation, skin sensitization, and acute toxicity — directly from molecular structure (SMILES), by computing molecular descriptors and molecular fingerprints and feeding them into a Soft-Voting Ensemble classifier.

A key strength of the system is its adherence to the five **OECD principles for QSAR validation**, in particular the presence of a defined **Applicability Domain (AD)** and a **three-layer confidence system**, allowing the platform to explicitly flag when a query substance lies outside the region in which the model is reliable. RalphGuard further integrates additional AI technologies: a **conversational AI assistant (NLP/Chatbot)** that executes natural-language Thai commands, **speech technology (TTS/STT)**, and **image processing (OCR)** that reads ingredient lists from product-label photographs and converts them into an assessable formula. All results are visualized on an interactive **3D facial model** for intuitive interpretation. In evaluation, the four models achieved out-of-fold AUC scores between 0.886 and 0.926, sufficient for use as a first-tier screening tool prior to physical testing.

**Keywords:** QSAR, In-silico Screening, Alternatives to Animal Testing, Chemical Toxicity, Applicability Domain, Machine Learning, OCR Image Processing, Artificial Intelligence

## 1. บทนำ (แนวคิด ความสำคัญ และความเป็นมาของโครงการ)

การประเมินความปลอดภัยของสารเคมี เครื่องสำอาง และผลิตภัณฑ์ที่สัมผัสผิวหนังหรือดวงตา เป็นขั้นตอนบังคับก่อนออกสู่ตลาด โดยวิธีมาตรฐานดั้งเดิม เช่น **Draize Test (OECD TG 404/405)** และ **LLNA (TG 429)** ต้องทดลองกับสัตว์ ทำให้เกิดปัญหา 3 ด้านหลัก ได้แก่ (1) **ด้านจริยธรรม** — สัตว์ทดลองต้องทนความเจ็บปวด (2) **ด้านต้นทุนและเวลา** — การทดสอบชุดหนึ่งใช้เวลาเป็นสัปดาห์ถึงเดือนและมีค่าใช้จ่ายสูง และ (3) **ด้านกฎระเบียบ** — หลายประเทศ (เช่น สหภาพยุโรปตั้งแต่ปี 2013) ห้ามการทดลองเครื่องสำอางในสัตว์ ผลักดันให้ต้องหาวิธีทดแทน (Alternative Methods)

แนวทางที่ได้รับการยอมรับระดับสากลคือ **New Approach Methodologies (NAMs)** ซึ่งรวมถึงวิธี **in-silico** หรือการทำนายด้วยแบบจำลองคอมพิวเตอร์จากโครงสร้างโมเลกุล โดยอาศัยหลักการที่ว่า "โครงสร้างทางเคมีที่คล้ายกันมักมีฤทธิ์ทางชีวภาพที่คล้ายกัน" (Structure–Activity Relationship)

**RalphGuard** เกิดขึ้นเพื่อทำให้เทคโนโลยี in-silico ที่ปกติอยู่ในห้องวิจัยและต้องใช้ความเชี่ยวชาญสูง กลายเป็น**เครื่องมือที่ผู้พัฒนาผลิตภัณฑ์ทั่วไปใช้ได้ผ่านเว็บ** — เพียงป้อนชื่อสาร/SMILES/ไฟล์ CSV หรือถ่ายรูปฉลากส่วนผสม ระบบก็จะประเมินความเสี่ยง 4 ด้านให้ พร้อมบอกระดับความเชื่อมั่นของผลลัพธ์ และแสดงผลบนแบบจำลอง 3 มิติที่เข้าใจง่าย ช่วยให้ผู้พัฒนาปรับสูตรให้ปลอดภัยขึ้นก่อนนำไปทดสอบจริง จึงลดจำนวนการทดลองในสัตว์ ลดต้นทุน และเร่งกระบวนการพัฒนาผลิตภัณฑ์

## 3. รายละเอียดของการพัฒนา

### 3.1 เนื้อเรื่องย่อ (Story Board) และภาพรวมระบบ

ผู้ใช้เข้าสู่ระบบผ่านหน้าเว็บ แล้วดำเนินงานตามลำดับ 5 ขั้น:

```
ขั้นที่ 1  ป้อนส่วนผสม        → พิมพ์ชื่อสาร/SMILES, อัปโหลด CSV, หรือถ่ายรูปฉลาก (OCR)
ขั้นที่ 2  ตรวจสอบโครงสร้าง    → RDKit ตรวจ SMILES + คำนวณ descriptors/fingerprints
ขั้นที่ 3  จำลอง (in-silico)  → แบบจำลอง QSAR ทำนายความเสี่ยง 4 ด้าน + Applicability Domain
ขั้นที่ 4  แสดงผล 3 มิติ       → ระบายผลลงบนแบบจำลองใบหน้า (บวม/แดงตามระดับความเสี่ยง)
ขั้นที่ 5  รายงาน             → กราฟแนวโน้ม, ระดับความเชื่อมั่น, ส่งออกรายงาน PDF
```

**โมดูลหลักของระบบ (Studio):**

- **โหมดประเมิน (Assess):** จัดการสูตร (เพิ่ม/ลบ/แก้ไข/เปลี่ยนชื่อ) โดยมีน้ำ (Water/Aqua) เป็นเบสที่ปรับสัดส่วนให้ครบ 100% อัตโนมัติ, ระบายผลลงหุ่น 3 มิติ, ยางลบ, กราฟแนวโน้ม Day 1/3/7
- **โหมด Nodes:** สร้างสูตรแบบ node graph (Blender-style) เชื่อมสาร → ตัวปรับ (modifier) → ผลการประเมิน ทำให้ "อัลกอริทึมที่ชัดเจน" ของ QSAR มองเห็นเป็นภาพ (สอดคล้อง OECD Principle 2)
- **ผู้ช่วย AI "แรลฟ์":** สนทนาภาษาไทย ตอบคำถามจากบริบทผลประเมิน และ**ลงมือทำได้จริง** (สร้าง/แก้สูตร, ปรับความเข้มข้น, เปลี่ยนสาร, รันประเมิน) รับ-ตอบด้วยเสียงได้
- **สแกนฉลาก (OCR):** ถ่าย/อัปโหลดรูปฉลากส่วนผสม → อ่านตัวอักษร → แปลงชื่อ INCI เป็น SMILES → ประเมิน

### 3.2 ทฤษฎี หลักการ และเทคโนโลยีที่ใช้

#### 3.2.1 QSAR (Quantitative Structure–Activity Relationship)

QSAR เป็นการสร้างความสัมพันธ์เชิงปริมาณระหว่าง**โครงสร้างโมเลกุล**กับ**ฤทธิ์ทางชีวภาพ** โดยแปลงโมเลกุลเป็นตัวเลข (features) แล้วใช้แบบจำลองทางสถิติ/แมชชีนเลิร์นนิงทำนายผล ระบบทำตามหลักการตรวจสอบ QSAR ของ OECD ครบทั้ง 5 ข้อ:

1. **Endpoint ที่นิยามชัดเจน** — 4 endpoint อ้างอิงเกณฑ์ GHS/OECD
2. **อัลกอริทึมที่ไม่กำกวม** — เปิดเผยขั้นตอนผ่านโหมด Node Graph และโค้ด
3. **Applicability Domain ที่นิยามชัดเจน** — k-NN Tanimoto (ดู 3.2.4)
4. **มาตรวัดความแม่นยำ/ความทนทาน/การทำนาย** — 5-fold out-of-fold (ดูหัวข้อ 5)
5. **การตีความเชิงกลไก** — มี rule-based structural alerts ประกอบ

#### 3.2.2 การแทนค่าโมเลกุล (Molecular Representation)

- **SMILES** (Simplified Molecular Input Line Entry System) — สายอักขระแทนโครงสร้างโมเลกุล เช่น เอทานอล = `CCO`
- **Molecular Descriptors** — ค่าคุณสมบัติเชิงกายภาพ-เคมี เช่น น้ำหนักโมเลกุล (MW), ค่าการละลายในไขมัน (logP), พื้นที่ผิวเชิงขั้ว (TPSA), จำนวนพันธะไฮโดรเจนให้/รับ (HBD/HBA)
- **Molecular Fingerprints** — เวกเตอร์บิตแทนโครงสร้างย่อย: **Morgan/ECFP** (2048 บิต, รัศมี 2) และ **MACCS keys** (167 บิต)

การเลือก feature ต่อ endpoint: skin/eye → MACCS + descriptors, sens → Morgan, acute → Morgan + MACCS + descriptors

#### 3.2.3 แบบจำลอง (Soft-Voting Ensemble)

แต่ละ endpoint ใช้ **Soft-Voting Ensemble** ที่รวมแบบจำลอง 4 ตัว (ทุกตัวใช้ class weight แบบ balanced):

- Random Forest
- Extra Trees
- Logistic Regression
- Histogram-based Gradient Boosting

เลือก **operating threshold** ต่อ endpoint ด้วย **Youden's J** จากผล 5-fold out-of-fold เพื่อให้ smดุลระหว่างความไว (sensitivity) และความจำเพาะ (specificity)

#### 3.2.4 Applicability Domain (AD) และระบบความเชื่อมั่น 3 ชั้น

- **Applicability Domain** — ใช้วิธี k-NN Tanimoto: คำนวณความคล้าย Tanimoto ของโมเลกุลที่ถามกับเพื่อนบ้านใกล้สุด k=5 ตัวในชุดเทรน หากค่าเฉลี่ยความคล้าย ≥ threshold (ตั้งไว้ 0.18 ให้เหมาะกับขนาดชุดข้อมูล) ถือว่า "in-domain" มิฉะนั้น "out-of-domain" (OECD Principle 3)
- **ระบบความเชื่อมั่น 3 ชั้น** — รวม 3 สัญญาณเป็นระดับ สูง/กลาง/ต่ำ:
  - ชั้นที่ 1: Applicability Domain (ใน/นอกขอบเขต)
  - ชั้นที่ 2: ความชัดของค่าความน่าจะเป็น (extreme vs borderline)
  - ชั้นที่ 3: ความสอดคล้องกับ rule-based structural alerts
- ระบบแสดงความเชื่อมั่น **3 ระดับ**: ต่อสาร, ต่อ endpoint, และ**ต่อสูตรทั้งหมด** (แบนเนอร์เตือนเมื่อสารส่วนใหญ่นอกขอบเขต — ป้องกันการอ่านคะแนนต่ำแล้วเข้าใจผิดว่าปลอดภัย)

#### 3.2.5 แบบจำลองความเสี่ยงของสูตรผสม (Mixture Model)

คำนวณความเสี่ยงของสูตรรวมด้วยหลัก **dose-additivity ถ่วงน้ำหนักด้วยความเข้มข้น**:

```
peak_endpoint = Σ ( ความเข้มข้น_i / 100 × potency_i_endpoint )
```

จากนั้นคูณด้วย **region sensitivity factor** สำหรับผิว/ตา (บริเวณต่างกันไวต่างกัน) และตัดค่าให้อยู่ในช่วง 0–100 ทั้งนี้ น้ำ (Water) มี potency = 0 จึงทำหน้าที่เป็นตัวเจือจาง

#### 3.2.6 เทคโนโลยีปัญญาประดิษฐ์เสริม

- **NLP / Chatbot (ผู้ช่วย AI "แรลฟ์"):** ใช้โมเดลภาษาขนาดใหญ่ (LLM) เข้าใจคำสั่งภาษาไทยธรรมชาติ แล้วแปลงเป็นการกระทำ (agentic actions) เช่น เพิ่ม/ลบ/ปรับความเข้มข้น/เปลี่ยนสาร/ตั้งชื่อสูตร/รันประเมิน โดยแนบคำสั่งในรูปแบบ structured tag ที่ frontend นำไปทำจริง
- **Speech Technology:** สังเคราะห์เสียงพูดภาษาไทย (TTS, เสียง neural) และรับคำสั่งด้วยเสียง (STT ผ่าน Web Speech API)
- **Image Processing (OCR):** อ่านตัวอักษรจากรูปฉลากด้วย Tesseract → แยกเฉพาะบล็อกรายการส่วนผสม → จับคู่ชื่อ INCI กับ SMILES ผ่านคลังภายใน (fuzzy matching) และ **PubChem API** (แปลงชื่อ→โครงสร้างแบบ runtime) พร้อม guard ป้องกันการจับผิด (คำกำกวม/เศษคำ/ข้อความขยะ)

#### 3.2.7 การแสดงผล 3 มิติ

ใช้ WebGL (Three.js / React Three Fiber) เรนเดอร์แบบจำลองใบหน้า และฉีด GLSL shader เพื่อระบายสี "แดง" และเพิ่ม "การบวม" (vertex displacement) ตามระดับความเสี่ยงที่จุดที่ผู้ใช้ระบาย พร้อม tooltip บอกบริเวณ

### 3.4 รายละเอียดโปรแกรมเชิงเทคนิค (Software Specification)

#### 3.4.1 Input / Output Specification

**Input**

- ชื่อสารเคมี / สายอักขระ **SMILES**
- ไฟล์ **CSV** รายการสาร + สัดส่วน (%)
- **รูปภาพฉลาก** (JPG/PNG) สำหรับ OCR
- คำสั่งภาษาไทย (ข้อความ/เสียง) ถึงผู้ช่วย AI
- บริเวณทดสอบ (ท่อนแขน/มือ/ใบหน้า/ดวงตา)

**Output**

- คะแนนความเสี่ยง 0–100 ต่อ endpoint พร้อมแถบระดับ (ต่ำ/กลาง/สูง/รุนแรง)
- ระดับความเชื่อมั่น + สถานะ Applicability Domain (ต่อสาร/ต่อ endpoint/ต่อสูตร)
- กราฟแนวโน้ม (Day 1/3/7)
- การแสดงผลบนแบบจำลอง 3 มิติ
- รายงานสรุปในรูปแบบ **PDF** (สร้างจาก template ที่ใส่ข้อมูลจริง)

#### 3.4.2 Functional Specification

1. จัดการสูตรหลายสูตร (สร้าง/เปลี่ยนชื่อ/ลบ/แก้ไข) + น้ำเบสอัตโนมัติ
2. ตรวจสอบความถูกต้องของ SMILES และคำนวณ descriptors/fingerprints
3. ทำนายความเสี่ยง 4 endpoint + Applicability Domain + ความเชื่อมั่น
4. สร้างสูตรแบบ node graph พร้อม "ตัวปรับ" ที่ลดฤทธิ์
5. ผู้ช่วย AI เชิงสนทนา + ปฏิบัติการตามคำสั่ง + เสียง (TTS/STT)
6. OCR อ่านฉลาก → แปลง INCI → SMILES → นำเข้าสูตร
7. ให้ AI ปรับอัตราส่วนสารให้สมจริง/ปลอดภัยที่สุดอัตโนมัติ
8. แสดงผล 3 มิติ + กราฟแนวโน้ม + ส่งออก PDF

#### 3.4.3 โครงสร้างของซอฟต์แวร์ (Design)

สถาปัตยกรรมแบบ 3 ชั้น แยก service ผ่าน Docker Compose:

```
[Web Frontend: Next.js]  ──HTTP──▶  [API: FastAPI]  ──▶  [PostgreSQL]
        │                                 │
        │                                 ├──▶  [Redis Queue]  ──▶  [Worker: scientific/QSAR]
        │                                 ├──▶  [LLM API (Chatbot)]
        │                                 ├──▶  [OCR + PubChem]
        └── WebGL 3D (Three.js)           └──▶  [TTS]
```

- **scientific/** (แยกโมดูล): `descriptors.py`, `fingerprints.py`, `featurizer.py`, `applicability.py`, `confidence.py`, `qsar/predictor.py`, `mixture.py`, `pipeline.py`, `worker.py`
- **backend/app/api/**: `assessments.py`, `substances.py`, `chat.py`, `tts.py`, `ocr.py`, `models.py`, `projects.py`
- การเทรนแบบจำลอง: `data_prep.py` (โหลด 4 ชุดข้อมูล → canonicalize/ตัดซ้ำ → featurize → เทรน ensemble → เลือก threshold → บันทึก bundle)

#### 3.4.4 ส่วนที่ทีมพัฒนาขึ้นเอง และแหล่งที่มาของโค้ดประกอบ

**พัฒนาขึ้นเองทั้งหมด:** ตรรกะ QSAR pipeline, การ featurize, ระบบ Applicability Domain + ความเชื่อมั่น 3 ชั้น, แบบจำลองความเสี่ยงของสูตรผสม, การคัดกรอง/จับคู่ชื่อ INCI ใน OCR (block isolation + guard), ระบบผู้ช่วย AI เชิงปฏิบัติการ (agent actions), การแสดงผล 3 มิติด้วย GLSL, และส่วนติดต่อผู้ใช้ทั้งหมด รวมถึงการคัดเลือก/จัดทำชุดข้อมูลจากสารอ้างอิง GHS/OECD

## 5. ผลของการทดสอบโปรแกรม

### 5.1 ผลการตรวจสอบแบบจำลอง (5-fold Out-of-Fold Validation)

| Endpoint | จำนวนสาร (pos/neg) | Accuracy | Balanced Acc | Sensitivity | Specificity | AUC | MCC | Threshold |
|---|---|---|---|---|---|---|---|---|
| ระคายเคืองผิว (skin) | 96 | 0.885 | 0.896 | 0.947 | 0.845 | **0.926** | 0.776 | 0.40 |
| ระคายเคืองตา (eye) | 107 | 0.804 | 0.816 | 0.886 | 0.746 | **0.886** | 0.623 | 0.35 |
| แพ้ผิวหนัง (sens) | 86 | 0.802 | 0.825 | 0.900 | 0.750 | **0.896** | 0.620 | 0.30 |
| พิษเฉียบพลัน (acute) | 81 | 0.877 | 0.873 | 0.862 | 0.885 | **0.903** | 0.736 | 0.45 |

> ค่าที่รายงานเป็นแบบ out-of-fold (ไม่ leak ข้อมูลทดสอบเข้าเทรน) ทุก endpoint มี AUC ≥ 0.88 ซึ่งบรรลุเป้าหมายที่ตั้งไว้ (≥ 0.80)

### 5.2 ผลการทดสอบเชิงระบบ (Functional Testing)

- **การประเมินสาร/สูตร:** ป้อน SMILES → ได้ผล 4 endpoint + ความเชื่อมั่น + การแสดงผล 3 มิติ ภายในไม่กี่วินาที ✔
- **Applicability Domain:** สารเครื่องสำอางทั่วไป (เอสเทอร์/แว็กซ์/วิตามินอี) จัดเป็น in-domain หลังปรับ threshold และขยายชุดข้อมูล ✔ สารแปลกใหม่ถูกแจ้ง out-of-domain ถูกต้อง ✔
- **OCR อ่านฉลากจริง:** ทดสอบกับฉลากผลิตภัณฑ์จริง (เช่นครีมบำรุงผิว) — อ่านและจับคู่ส่วนผสมได้ถูกต้อง หลังใส่ guard สามารถตัดคำโฆษณา/ที่อยู่/ชื่อครึ่งคำ (เช่นไม่จับ "Alcohol" จาก "Lanolin Alcohol") ได้ ✔
- **ผู้ช่วย AI:** สั่งงานภาษาไทยหลายคำสั่งในประโยคเดียว (ลด/เปลี่ยน/เติมสาร + ตั้งชื่อ + รัน) ทำได้ครบ ✔ พร้อมตอบด้วยเสียง ✔

### 5.3 ตัวอย่างการค้นพบระหว่างทดสอบ (Validation Insight)

การทดสอบกับผลิตภัณฑ์จริงเผยให้เห็นความสำคัญของ Applicability Domain: ผลิตภัณฑ์มอยส์เจอไรเซอร์ที่อ่อนโยนอาจได้คะแนน "ต่ำ" เพราะสารบางตัวอยู่นอกขอบเขต (โมเดลเดาว่าไม่ระคาย) ระบบจึงแจ้งเตือน "เชื่อถือได้ต่ำ" อย่างถูกต้อง — สะท้อนว่าระบบ "รู้ขีดจำกัดของตัวเอง" ซึ่งเป็นหัวใจของการนำ QSAR ไปใช้อย่างรับผิดชอบ

## 6. ปัญหาและอุปสรรค

1. **ชุดข้อมูลจำกัด:** ข้อมูลพิษวิทยาที่มี ground truth ที่เชื่อถือได้และเปิดสาธารณะมีไม่มาก ทำให้ Applicability Domain แคบ แก้ไขเบื้องต้นด้วยการคัดสารอ้างอิง GHS/OECD เองและปรับ threshold ให้เหมาะกับขนาดชุด
2. **การจับคู่ชื่อ INCI ↔ โครงสร้าง:** ชื่อการค้า/INCI ไม่ตรงกับชื่อในฐานเคมีเสมอ และ OCR อาจอ่านผิด แก้ด้วย fuzzy matching + PubChem + guard ป้องกันการจับครึ่งคำ/ขยะ
3. **ความหลากหลายของสารในผลิตภัณฑ์จริง:** พอลิเมอร์/สารสกัด/ซิลิโคน ไม่มีโครงสร้างเดี่ยว ประเมินตรงไม่ได้ ระบบจึงจัดเป็น "รู้จักแต่ไม่มีโครงสร้าง" หรือ out-of-domain
4. **การแสดงผล 3 มิติ:** การทำให้พื้นผิว "บวม-แดง" ดูสมจริง (โค้งมน ไม่เป็นเหลี่ยม) ต้องปรับ shader และ vertex displacement หลายรอบ
5. **เสถียรภาพของบริการภายนอก:** LLM/PubChem ต้องต่ออินเทอร์เน็ต จึงออกแบบให้ degrade ได้ (มีคลังภายในสำรอง)

3. **โมดูล Organ-on-a-Chip เสมือน** จำลองการซึมผ่านเนื้อเยื่อหลายอวัยวะ (ผิว/ตา/ตับ) เชิง in-silico
4. **เชื่อมต่อ QSAR Toolbox / read-across** เพื่อการอ่านข้ามสารตามหลัก OECD
5. **ถ่วงน้ำหนักผลด้วยความเชื่อมั่น** และเพิ่มการอธิบายเชิงกลไก (mechanistic interpretation) ที่ละเอียดขึ้น
6. **ประยุกต์กับอุตสาหกรรม** เครื่องสำอาง อาหาร ยา และการคัดกรองสารเคมีในสิ่งแวดล้อม

## 8. ข้อสรุปและข้อเสนอแนะ

RalphGuard แสดงให้เห็นว่าการนำ QSAR + Machine Learning มาบรรจุในเว็บที่ใช้ง่าย สามารถช่วย**คัดกรองความเสี่ยงของสารเคมีและสูตรผลิตภัณฑ์เบื้องต้นได้โดยไม่ต้องทดลองในสัตว์** พร้อมทั้งรายงานความเชื่อมั่นและขอบเขตการใช้งานอย่างโปร่งใสตามหลัก OECD ระบบยังผสานเทคโนโลยี AI ครบทั้งด้านภาษา (NLP/Chatbot), เสียง (TTS/STT) และการประมวลผลภาพ (OCR) ทำให้เข้าถึงง่ายสำหรับผู้ใช้ทั่วไป

**ข้อเสนอแนะ:** ควรใช้ระบบเป็นเครื่องมือคัดกรองก่อนการทดสอบจริงเสมอ ไม่ตีความผลเดี่ยว ๆ โดยไม่ดูระดับความเชื่อมั่น และการพัฒนาขั้นต่อไปควรให้ความสำคัญกับการขยายชุดข้อมูลเพื่อให้ Applicability Domain ครอบคลุมสารจริงในตลาดมากขึ้น

## 11. ภาคผนวก (Appendix)

### 11.1 คู่มือการติดตั้ง (Installation Guide)

**ความต้องการเบื้องต้น:** Docker + Docker Compose, Node.js 18+, Git

```bash
# 1) โคลนโปรเจกต์
git clone <repository-url> ralphguard
cd ralphguard

# 2) ตั้งค่าตัวแปรสภาพแวดล้อม (ไฟล์ .env ที่ราก)
#    GROQ_API_KEY=<คีย์ LLM ของคุณ>
#    GROQ_MODEL=llama-3.3-70b-versatile
#    CORS_ORIGINS=http://localhost:3000

# 3) เทรนแบบจำลอง (ครั้งแรก) ผ่าน worker เพื่อให้เวอร์ชันไลบรารีตรง runtime
python data_prep.py          # สร้าง scientific/models/*.pkl + validation_report.json

# 4) ยกระบบทั้งหมดด้วย Docker
docker compose up -d --build   # postgres, redis, backend, worker

# 5) รันฝั่งเว็บ
cd frontend && npm install && npm run dev
#   เปิด http://localhost:3000
```

> หมายเหตุ: backend มีการติดตั้ง `tesseract-ocr` ใน Dockerfile สำหรับฟังก์ชัน OCR แล้ว

### 11.2 คู่มือการใช้งาน (User Guide) โดยย่อ

1. เข้าหน้า **/assess** (Studio)
2. **สร้างสูตร** — กด "＋ สร้างสูตร" ตั้งชื่อและประเภท หรือ **สแกนฉลาก** (ปุ่ม 📷 อ่านฉลากส่วนผสมจากรูป) แล้วอัปโหลดรูป → ระบบสแกน → ยืนยัน "ใช้งานได้/ไม่ได้" → เพิ่มเข้าสูตร
3. (ถ้าต้องการ) กด **🤖 ใช้ AI ปรับอัตราส่วนสารอัตโนมัติ** เพื่อปรับ % ให้สมจริง
4. เลือกบริเวณทดสอบ แล้วกด **▶ Run ประเมิน**
5. อ่านผล 4 endpoint + **ระดับความเชื่อมั่น/Applicability Domain** (ต่อสาร/ต่อ endpoint/ต่อสูตร) และดูการแสดงผลบนหุ่น 3 มิติ
6. ดู **กราฟแนวโน้ม** (Day 1/3/7) และกด **แชร์ / PDF** เพื่อส่งออกรายงาน
7. สอบถาม/สั่งงาน **ผู้ช่วย AI "แรลฟ์"** ด้วยข้อความหรือเสียง

### 11.3 ข้อตกลงในการใช้ซอฟต์แวร์ (Disclaimer)

RalphGuard เป็นเครื่องมือ**คัดกรองความเสี่ยงเบื้องต้นด้วยแบบจำลองคอมพิวเตอร์ (in-silico)** เท่านั้น ผลลัพธ์ที่ได้เป็นการประมาณการเชิงคำนวณ **ไม่สามารถทดแทนการทดสอบจริงตามมาตรฐาน** และ**ไม่ใช่คำวินิจฉัยหรือคำแนะนำทางการแพทย์** ผู้ใช้ต้องพิจารณาระดับความเชื่อมั่น/ขอบเขตการใช้งานประกอบเสมอ คณะผู้พัฒนาไม่รับผิดชอบต่อความเสียหายใด ๆ ที่เกิดจากการตีความหรือนำผลไปใช้โดยไม่ผ่านการทดสอบยืนยัน
