## P0 — ความถูกต้องและการไม่สูญหายของข้อมูล

### 1. บันทึก Workspace แยกตามโปรเจกต์

ระบบบันทึกและกู้ข้อมูลต่อไปนี้โดยอ้างอิง `projectId`:

- กล่องสูตร ชื่อสูตร ประเภทผลิตภัณฑ์ และสูตรที่กำลังเลือก
- รายการสาร SMILES และเปอร์เซ็นต์
- บริเวณทดสอบและวันที่เลือก Day 1, Day 3 หรือ Day 7
- โหมดการทำงาน ผลประเมินล่าสุด และสถานะงานที่กำลังประเมิน
- รอยที่ทาบนโมเดลของแต่ละสูตร
- Nodes, edges, viewport และผลของ Node graph

ผลที่ได้:

- กด F5 แล้วข้อมูลสำคัญไม่หาย
- เปิดโปรเจกต์อื่นแล้วข้อมูลไม่ปะปนกัน
- ลบโปรเจกต์แล้ว workspace ฝั่ง browser ของโปรเจกต์นั้นถูกลบตาม
- ข้อมูลเก่าที่รูปแบบไม่ถูกต้องถูก normalize หรือปฏิเสธอย่างปลอดภัย

### 2. ผูกผลประเมินกับสูตรและข้อมูลที่ใช้ประเมินจริง

- ผลประเมินถูกแยกตามกล่องสูตร ไม่ใช้ผลเดียวร่วมกันทั้งหน้า
- บันทึก signature ของชื่อสาร SMILES เปอร์เซ็นต์ และบริเวณทดสอบ
- เมื่อเพิ่มสาร ลบสาร แก้เปอร์เซ็นต์ เปลี่ยนสูตร หรือเปลี่ยนข้อมูลสำคัญ ผลเดิมของสูตรนั้นจะถูกยกเลิก
- ป้องกันผลจาก request เก่ากลับมาเขียนทับสูตรที่ผู้ใช้กำลังแก้ไข
- เมื่อสลับสูตร ผลและรอยของสูตรอื่นยังคงอยู่ ไม่ถูกลบโดยไม่ตั้งใจ

### 3. ตรวจเงื่อนไขก่อนเริ่มประเมิน

ปุ่มประเมินยังสามารถกดได้ แต่ระบบจะแจ้ง Toaster ที่อธิบายสิ่งที่ขาดอย่างชัดเจน เช่น:

- ยังไม่ได้เลือกกล่องสูตร
- สูตรยังไม่มีสาร
- ยังไม่ได้ทาสารลงบนโมเดล
- มีงานประเมินของสูตรนี้กำลังทำงานอยู่
- ข้อมูลสารหรือเปอร์เซ็นต์ไม่ถูกต้อง

เมื่อ Backend ประเมินสำเร็จ ระบบจะแจ้งว่าการวิเคราะห์เสร็จสิ้น และเมื่อเกิดข้อผิดพลาดจะแสดงข้อความที่อ่านเข้าใจได้

### 4. จัดการรอยทาหลายสูตรบนโมเดลเดียวกัน

- โมเดลแสดงรอยจากหลายกล่องสูตรพร้อมกันได้
- แต่ละรอยมีเจ้าของเป็นกล่องสูตรที่ใช้ทา
- ป้องกันการทาของสองสูตรทับตำแหน่งเดียวกัน
- ยางลบของสูตรที่เลือกไม่ลบรอยของสูตรอื่น
- ยางลบสามารถลบรอยครีมสีขาวก่อนกดประเมินได้ทันที
- รองรับการล้างรอยของสูตรที่เลือกและล้างรอยทั้งหมด
- การล้างรอยรวมถึงอาการบริเวณดวงตา ไม่เหลือผลเก่าค้างอยู่
- หลังทารอยใหม่ ระบบจะยังไม่แสดงอาการจนกว่าจะกดเริ่มทดสอบอีกครั้ง

## P1 — ความต่อเนื่องของงานและความน่าเชื่อถือของผลลัพธ์

### 5. กู้สถานะการประเมินหลัง F5

- บันทึก job ID, เวลาเริ่มงาน, formula ID และ input signature
- หลัง F5 ระบบสามารถกลับไปติดตามงานเดิมแทนการเริ่มงานซ้ำ
- ใช้ polling delay แบบเพิ่มช่วงเวลาเพื่อลด request ที่ไม่จำเป็น
- หยุดงานที่ค้างเกินเวลาที่กำหนด
- ยกเลิก request เมื่อออกจากหน้า และไม่แสดง error จาก request ที่ถูกยกเลิกตามปกติ

### 6. ทำให้โปรเจกต์และรายงานอ้างอิงข้อมูลจริง

- ยกเลิกการสร้างโปรเจกต์แบบ `local-*` เมื่อ Backend ไม่พร้อม
- แยกสถานะ Backend ใช้งานไม่ได้ออกจากสถานะไม่มีข้อมูล
- ตรวจ project ID จาก URL ก่อนโหลดหน้า
- ปฏิเสธชื่อโปรเจกต์ที่ว่างหรือมีแต่ช่องว่างทั้ง Frontend และ Backend
- รายงานเปิดด้วย assessment ID ที่ชัดเจน
- Backend ตรวจว่าผลประเมินเป็นของโปรเจกต์ที่ร้องขอจริง
- หน้า results และ history เลือกผลที่เสร็จสมบูรณ์จริง โดยไม่ใช้ sample fallback

## P2 — เครื่องมือนำเข้าข้อมูลและโหมด Node

### 7. CSV Import

- แยก parser กลางไว้ที่ `frontend/src/lib/formula-csv.ts`
- รองรับ `name`, `smiles`, `concentration` และชื่อคอลัมน์ alias ที่กำหนด
- ตรวจ schema, แถวว่าง, ตัวเลขผิดรูปแบบ, เปอร์เซ็นต์เกินช่วง, ผลรวมเกิน 100%, จำนวนสารเกินกำหนด และสารซ้ำ
- นำเข้าไปยังกล่องสูตรที่เลือกตอนเริ่มอ่านไฟล์ ป้องกันการสลับสูตรระหว่างอ่านแล้วข้อมูลลงผิดกล่อง

### 8. OCR ฉลาก

- กำหนดพฤติกรรม OCR ให้แทนที่รายการสารของกล่องเป้าหมายอย่างชัดเจน
- ผูกผล OCR กับโปรเจกต์และกล่องสูตรต้นทาง
- ยกเลิก request ได้เมื่อปิดหน้าต่าง
- รายงานสารซ้ำ ไม่มี SMILES จับคู่ไม่ได้ หรือมี concentration ไม่ถูกต้อง
- รองรับการนำเข้าบางส่วนพร้อมสรุปรายการที่ถูกข้าม

### 9. Node graph ที่ sync กับกล่องสูตรที่เลือก

- Node graph แยกข้อมูลตามโปรเจกต์และกล่องสูตร
- เมื่อเลือกสูตร A หรือ B โหนดสารจะแสดงและแก้ไขข้อมูลของสูตรนั้น
- การเพิ่ม แก้ หรือลบ chemical node sync กลับไปยังกล่องสูตรที่เลือก
- เมื่อแก้สูตรจากฝั่งกล่อง รายการ chemical node ถูก sync ตาม
- เก็บตำแหน่ง node, edge, viewport และผลประเมินของกราฟหลัง F5
- ป้องกันผล Node เก่าค้างเมื่อองค์ประกอบสูตรเปลี่ยน

## P3 — ความทนทานของหน้าและ Request

### 10. Route และ Request reliability

- เพิ่ม loading และ error boundary ของ route สำคัญ
- รองรับ `AbortSignal` จาก caller ใน API client
- ป้องกันการกด mutation ซ้ำและ response เก่าเขียนทับข้อมูลใหม่
- เพิ่มข้อความ timeout ที่เข้าใจง่าย
- logging ไม่แสดง API key หรือข้อมูลลับจาก error response
- ตรวจ job ID และ input signature ก่อนรับผล polling ทุกครั้ง

### 11. Automated tests และ TypeScript

- Frontend logic tests ผ่าน 43/43 ตามสถานะในแผนงาน
- Backend tests ผ่าน 15/15 ตามสถานะในแผนงาน
- แก้ TypeScript error เดิมใน `TrendChart.tsx`
- baseline `npm run type-check` ผ่าน

## P4 — Branding และประสบการณ์ใช้งาน

### 12. Branding และ Navigation

- ใช้ `logo.png` ของ RalphGuard ใน Navbar, Dashboard, หน้า Projects, Loading และรายงาน PDF
- ปุ่มหน้าแรกและโลโก้ในส่วนที่เกี่ยวข้องพาไป `/projects`
- นำเมนูหน้าแรกที่ซ้ำซ้อนออกจาก sidebar ของหน้า Projects
- นำข้อความ `UI Preview` ออกจาก header
- ใช้ LINE Seed Sans TH เป็น font หลัก และนำตัวแปร font รุ่นที่ไม่มีหัวออก

### 13. ใช้ Icon แทน Emoji

- เพิ่ม `SemanticIcon` เป็นแหล่งรวม Lucide icon ที่ใช้ซ้ำได้
- เปลี่ยน emoji ในหน้า Assessment, Node graph, OCR, AI assistant, รายงาน และส่วนประกอบอื่นเป็น icon
- เพิ่มไอคอนถังขยะสำหรับการลบสูตร

### 14. Loading และการเปลี่ยนสถานะของหน้า

- เพิ่ม `BrandedProgressLoader` ที่ใช้ซ้ำได้
- แสดงโลโก้ Progress bar และข้อความ “กำลังโหลดข้อมูลล่าสุด” เมื่อเข้าโปรเจกต์
- ลดความยาว Progress bar และเพิ่มขนาดโลโก้ตามสัดส่วนที่อ่านง่าย
- เอาพื้นหลังลายตารางออกระหว่างโหลดโมเดล 3D

### 15. Slide panel และพื้นที่โมเดล

- แผง “ส่วนผสมของสูตร” เริ่มต้นแบบปิดทุกครั้งเมื่อเข้าโปรเจกต์
- แก้ z-index และ overflow ไม่ให้แผงทับ header หรือพื้นที่ฝั่งซ้าย
- เมื่อเปิดหรือปิดแผง พื้นที่โมเดล จุดแนะนำ และ legend เคลื่อนตำแหน่งด้วย transition เดียวกัน
- การเคลื่อนโมเดลจึงนุ่มขึ้นและไม่กระตุกทันที
- คลังสารเปิดไปทางขวาของปุ่ม ไม่ไหลลงด้านล่าง

### 16. การรักษาโมเดลขณะสลับสูตร

- นำการ remount โมเดลจากการเปลี่ยน formula key ออก
- การสลับสูตรเปลี่ยนเฉพาะ mask และข้อมูลของสูตรใน renderer เดิม
- กล้อง มุมหมุน WebGL context และโมเดล GLB ไม่ถูกโหลดใหม่ทุกครั้ง

### 17. Animation ของสูตร

- Modal สร้างสูตรมี fade, zoom และ slide animation ตอนเปิด
- กล่องสูตรใหม่มี animation และ ring ชั่วคราวเพื่อให้ผู้ใช้เห็นตำแหน่งที่เพิ่ม
- แถวสารที่เพิ่มด้วยปุ่ม “เพิ่มสาร” หรือเลือกจากคลังสาร จะ fade และเลื่อนเข้าจากด้านขวา
- แถวใหม่มีสีและกรอบแบรนด์ชั่วคราว 0.7 วินาที แล้วค่อยกลับเป็นสีปกติ
- รองรับ `prefers-reduced-motion`

### 18. การลบสูตรอย่างปลอดภัย

- เปลี่ยนปุ่มลบจากเครื่องหมายกากบาทเป็นไอคอนถังขยะ
- สูตรว่างสามารถลบได้ทันที
- สูตรที่มีสารจะแสดง Alert Dialog พร้อมชื่อสูตรและจำนวนสารก่อนลบ
- Dialog แจ้งว่าผลประเมิน รอยที่ทา และข้อมูลของสูตรจะถูกลบด้วย
- เมื่อยืนยัน ระบบใช้ logic ลบเดิมเพื่อเคลียร์ assessment, paint mask และ graph ของสูตรนั้นทั้งหมด

### 19. ระยะกล้องเริ่มต้นของโมเดล 3D

- ปรับโมเดลในหน้า Assessment ให้แสดงใกล้ขึ้นประมาณภาพอ้างอิงล่าสุด
- เปลี่ยน camera fit distance จากค่า scale ปกติ `1.5` เป็น `1.15` เฉพาะหน้าประเมิน
- โมเดลมีขนาดใหญ่ขึ้นประมาณ 30% โดยยังหมุนและซูมเองได้ตามเดิม
- ไม่กระทบตำแหน่งรอยทา การสลับสูตร หรือกล้องของหน้า Symptom Lab แบบ standalone
